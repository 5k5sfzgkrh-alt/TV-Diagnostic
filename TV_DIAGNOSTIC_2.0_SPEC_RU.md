# TV Diagnostic 2.0 — спецификация и границы безопасности

Цель: доказательная диагностика Android TV на плате CS2352P687 / платформе HiSilicon Hi3751V553 и сбор данных для анализа прошивки.

## Реализовано в 2.0.1 (исходный код; требуется физическая проверка на телевизоре)
- Базовый снимок Build fingerprint, Android/API, ABI, RAM, /data storage.
- Список установленных пакетов, системный флаг, enabled, sourceDir, запрошенные permissions и количества services/receivers/providers.
- Список процессов, видимых обычному приложению (не полный системный список).
- ROOT-аудит через фиксированный сценарий чтения: getprop, cpuinfo, meminfo, partitions, mounts, modules, cmdline, DT model/compatible, block/by-name, network interfaces, sysfs DRM/framebuffer, fstab, VINTF manifests, init listing/script, build.prop, отфильтрованные сообщения dmesg.
- QR/Wi-Fi передача текущего JSON через локальный HTTP endpoint с случайным одноразовым токеном; один успешный запрос завершает сервер. Кнопка остановки закрывает сервер вручную.
- Экспорт JSON через Android share chooser.
- Режим READ_ONLY: команды изменения пакетов, свойств, монтирования, разделов и загрузчика отсутствуют.

## QR / Wi-Fi
1. Телевизор и телефон должны находиться в одной локальной сети.
2. На ТВ запустить «Передать отчёт: QR / Wi-Fi».
3. Отсканировать QR телефоном и скачать JSON в браузере.
4. После успешного скачивания сервер автоматически закрывается; его также можно остановить кнопкой.
5. Если роутер изолирует Wi-Fi-клиентов или сеть запрещает входящие соединения, передача не сработает. Использовать доверенную домашнюю сеть; не публиковать QR в интернете.

## Ограничения и безопасность
- ROOT-аудит запускается только по нажатию пользователя и использует фиксированный встроенный сценарий. Никакой произвольной команды из UI/сети не принимается.
- Android может ограничивать доступ даже root-командам (SELinux, kernel config, vendor permissions); недоступные данные должны оставаться явно неизвестными.
- Доступность root-пути «su -c» должна быть проверена на конкретном телевизоре.
- Отсутствие компонента в снимке не доказывает его отсутствие.
- Файлы DT compatible могут содержать бинарные разделители; интерпретация должна учитывать формат.
- QR/Wi-Fi сервер локальный, без TLS; защита основана на одноразовом случайном токене и доверенной локальной сети. Это не следует использовать в публичной/гостевой сети.

## Политика решений
- GREEN: не присваивать в этой версии. Нужны полные APK manifests, providers/receivers/services, shared UID, библиотеки, overlays/sysconfig/init/VINTF зависимости и практические тесты на ТВ.
- YELLOW: недостаточно доказательств, нужна проверка.
- RED: загрузка, дисплей, аудио, TV/tuner, сеть, HAL, драйверы, системный UI, framework, init, firmware и partition metadata.
- GRAY: назначение не установлено.

## Неприкосновенные ограничения
Нет pm disable/uninstall, setprop, remount, dd, flash, fastboot, записи в /dev/block, удаления или изменения системных файлов. Автоотключение не реализовано.

## Не реализовано / требует отдельного этапа
- Полноценный статический анализ бинарных APK manifests, сертификатов, overlays, sysconfig и графа зависимостей из исходных SYSTEM/VENDOR.
- Полная расшифровка vendor-specific panelparam/tconparam/demura, boot/recovery/vbmeta и proprietary bootloader metadata.
- Автоматическое определение физической ревизии PCB и модели панели без соответствующих маркировок/EDID/vendor panel tables.
- Проверка на реальном ТВ, разных Android permission paths и сетевых конфигурациях.
- Восстановление прежних функций резервного копирования из 1.6.2: исходники 1.6.2 пока не найдены в доступной ветке и нельзя утверждать, что они перенесены.

## Сборка
GitHub Actions собирает debug APK и SHA-256. Успешная CI-сборка не является подтверждением работы ROOT и QR на физическом телевизоре.
